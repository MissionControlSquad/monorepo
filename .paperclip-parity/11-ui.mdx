# UI — Parity Gap Analysis

## TL;DR

Paperclip's UI is a **single-page React app** (`ui/src`, react-router) with ~90 route pages, ~250
shared components, a mature design system (`DesignGuide.tsx` = 87KB living showcase, `design-guide`
skill, design tokens, status/priority systems), and several *very deep* pages (`IssueDetail` 205KB,
`Secrets` 159KB, `CompanySkills` 193KB, `Pipelines` 211KB, `PipelineSettings` 152KB, `Inbox` 124KB,
`SkillStudio` 125KB, `AgentDetail` 171KB). Config/infra surfaces (environments, sandbox templates,
adapters, plugins/MCP, app connections, secret vaults) are first-class settings pages.

Our monorepo UI is a **Next.js app-router** app (`apps/web/app/(dashboard)/*` routes + thin
`apps/web/src/views` + `apps/web/src/components`) using `urql` against a co-located GraphQL server.
It has broad *breadth* — most epics have a route — but each page is 1 file, 100–600 lines, mostly a
flat list + form + a few `useMutation`s. Every page is flag-gated (`packages/utils/src/feature-flag-keys.ts`)
and admin-checked server-side. We have the plumbing (GraphQL ops for adapters, sandbox-providers,
secrets, plugins, skills, agent-memory) but the **rich config UIs are missing or stubbed**.

**Biggest UI gaps (config/infra, the focus areas):**

## 3. Gap deep-dive: Execution Environments UI ❌ (size **L**)

**Paperclip:** `CompanyEnvironments.tsx` at `/company/settings/instance/environments` (list/create/edit
modes), gated by `enableEnvironments` experimental flag. A user:
- creates named environments with a **driver**: `local` | `ssh` | `sandbox`;
- fills a driver-specific form — SSH (host/port/username/remote-path, key as literal or **secret ref**,
  known-hosts, strict-host-key) or **sandbox** (provider + provider JSON-schema config via `JsonSchemaForm`);
- edits **per-environment env vars** via the env-var editor (secret bindings + inline create-secret);
- **probes connectivity** for a saved env (`probe`) or a draft (`probeConfig`) with pass/fail toasts;
- sets the **instance-default** environment agents inherit;
- captures a **custom sandbox image/template** via `EnvironmentImageTemplatePanel`: start an interactive
  setup session on a sandbox provider, connect through an in-browser **xterm.js SSH terminal**, then
  Finish/Capture, Refresh, Rollback, or Disable a template (with "out of sync with config" warning).

**Monorepo:** nothing. `grep` for `companyEnvironment|environment.?variable` in `apps/web/app|src/views|src/components` = 0 hits. Sandbox *providers* exist server-side only
(`apps/web/src/server/graphql/queries/sandbox-providers.ts`, `mutations/sandbox-run.ts`) and are
surfaced merely as a per-agent dropdown in `runners/page.tsx` (`SET_AGENT_SANDBOX_PROVIDER`). There is
no notion of a reusable named execution environment in the UI.

**Impl plan:**
- Route: `apps/web/app/(dashboard)/environments/page.tsx` (+ `environments/[environmentId]/page.tsx` for edit) or nest under a settings route. View: `apps/web/src/views/EnvironmentsPage.tsx`; components `EnvironmentForm`, `SshDriverFields`, `SandboxDriverFields`, `EnvironmentProbeButton`, and (stretch) `EnvironmentImageTemplatePanel` reusing `components/terminals/*` for the xterm surface.
- GraphQL: new `queries/environments.ts` + `mutations/environments.ts` — `companyEnvironments`, `createEnvironment`, `updateEnvironment`, `deleteEnvironment`, `probeEnvironment`, `probeEnvironmentConfig`, `setDefaultEnvironment`, `startEnvironmentTemplateSession`/`captureEnvironmentTemplate`/`rollbackEnvironmentTemplate`. Reuse `SANDBOX_PROVIDERS_QUERY` for provider list + schema. Needs the `agent-templates`/sandbox services already present under `apps/web/src/server/services/sandbox/*`.
- Prereqs: port `JsonSchemaForm` (§2) and the env-var editor (§4).
- Gating: new flag `environments` in `feature-flag-keys.ts`; admin-only mutations server-side. Secret-ref fields require `secrets_vault`.
- Tests: form-render + driver switch, probe pass/fail toast, default-selection, template capture happy-path (mirror `CompanyEnvironments.test.tsx`, 52KB, as the spec source).

## 4. Gap deep-dive: Environment-variables editor component ❌ (size **M**)
