# Environments & Execution Targets — Paperclip → Monorepo Parity

## 0. Executive summary

Paperclip models **"where and how an agent run executes"** as a first-class, durable subsystem:
a normalized **Environment** (driver = `local` | `ssh` | `sandbox` | `plugin`), a **lease** that binds a
run to a live provider machine with reuse/retain policies, a **realized execution workspace**
(project-primary / git-worktree / adapter-managed / cloud-sandbox), **custom-image capture** with
interactive setup terminals, **probes**, an **execution allowlist / low-trust containment** security
layer, and a **plugin driver** RPC layer. Roughly **34 discrete capabilities**.

Our monorepo (Tier D) has deliberately ported the **thin ephemeral seam** — a `SandboxProvider`
registry (`local` + 7 cloud, BYO creds), `runTaskInSandbox` (provision→exec→destroy), `RunnerHost`
(BYO SSH), `RunnerCommand` (NAT-pull runner with atomic claim + reaper), a strong **adapter registry**
(`AgentAdapter` + `packages/utils/src/adapters.ts`), terminal sessions with live PTY, and a full
GraphQL + Runners UI — all `RUNNERS`/`TERMINALS`/`MULTI_PROVIDER_ADAPTERS` feature-gated. It
**intentionally dropped** the lease table, first-class Environment model, custom-image build, execution
workspaces, execution policy/allowlist, and probes (source-file headers say so explicitly).

Verdicts across 34 features: **✅ 4 · 🟡 14 · ❌ 16.** The four biggest missing pillars, in build order:
**(1) first-class Environment model + CRUD** (M), **(2) Environment lease lifecycle + reuse** (L),
**(3) Execution workspace model + strategies** (L), **(4) Execution policy / allowlist / low-trust
containment** (M). Custom-image capture (L) and probes (S) round out the depth gap.

> **Data-layer note:** Paperclip is **Drizzle**; our monorepo is **Prisma** (`packages/database/prisma/schema/*.prisma`).
> All plans below are written for Prisma + our Next.js/GraphQL shape.

### PLAN 1 — First-class Environment model + CRUD (features 1, 9, 10, 11, 12, 14, 17, 21) — **M**

The keystone. Everything downstream (leases, workspaces, policy) references `Environment`.

**Prisma** (`packages/database/prisma/schema/environment.prisma`):
```prisma
enum EnvironmentDriver { local ssh sandbox plugin }
enum EnvironmentStatus { active archived }

model Environment {
  id          String            @id @default(cuid())
  workspaceId String            // buildbase workspace _id; no FK (D5 convention)
  name        String
  description String?
  driver      EnvironmentDriver @default(local)
  status      EnvironmentStatus @default(active)
  config      Json              @default("{}")   // driver-specific; secrets stored as {secretRef}
  envVars     Json              @default("{}")   // merged into run env
  metadata    Json?
  createdByProfileId String?
  createdAt   DateTime          @default(now())
  updatedAt   DateTime          @updatedAt
  leases      EnvironmentLease[]
  @@unique([workspaceId, name])
  // partial-unique (one local / one managed-sandbox) via raw migration index
}
```
Add SQL partial-unique indexes (migration): one `driver='local'` and one managed `sandbox` per workspace
(mirrors `environments.ts:20,23`).

**Server services** (`apps/web/src/server/services/environments.ts` — new):
`listEnvironments`, `getEnvironment`, `createEnvironment` (validates driver config via zod schemas ported
from `environment-config.ts:39-140`), `updateEnvironment`, `ensureLocalEnvironment` (idempotent),
`ensureManagedSandboxEnvironment` (k8s), `getEnvironmentDeleteBlastRadius` (count active leases +
referencing agents), `removeEnvironmentIfDeletable`. Reuse the existing `sandbox-providers.ts` registry
to validate `driver:"sandbox"` `config.provider`. Config-secret handling reuses `resolveWorkspaceSecret`
+ a new `persistConfigSecretRefs`/`resolveConfigSecretRefs` helper (port `environment-config.ts:203,241`,
storing `{secretRef:{name}}` pointers into the vault instead of plaintext).

**GraphQL** (`apps/web/src/server/graphql/{queries,mutations}/environments.ts`):
- queries: `environments(workspaceId)`, `environment(id)`, `environmentCapabilities` (adapter×driver
  support matrix built from `listSandboxProviders` + adapter registry — feature 21).
- mutations: `createEnvironment`, `updateEnvironment`, `archiveEnvironment`, `deleteEnvironment`
  (guarded by blast-radius), `probeEnvironment` (Plan 4).
- Register in `queries/index.ts` + `mutations/index.ts`. Never return raw `config` secret values —
  return `configPublic` with secret paths masked.

**UI** (`apps/web/app/(dashboard)/environments/page.tsx` + `src/views/EnvironmentsView.tsx`):
- Environments list (name, driver badge, status, active-lease count), Create/Edit drawer with a
  driver-switch form (local | ssh | sandbox-provider | plugin), a **Probe** button (Plan 4), and a
  delete-confirm showing blast radius. New components: `EnvironmentDriverForm.tsx`,
  `EnvironmentCard.tsx`, `EnvironmentProbeResult.tsx`. Follow the `/design-guide` tokens; reuse the
  existing Runners-page data-fetching patterns.
- Add an **Environment** selector to the agent config card (`AgentAdapterConfigCard.tsx`) so an agent
  picks an environment instead of a bare `sandboxProvider`.

**Security:** gate on `ENVIRONMENTS` flag; admin-only mutations (reuse the Runners server-side admin
check). SSH private keys / provider API keys are written ONLY as vault secret-refs; the resolved
plaintext never leaves the server. `workspaceId` scoping on every query (multi-tenant isolation).

**Tests:** unit — driver-config zod validation (valid/invalid per driver), blast-radius counting,
secret-ref persist/resolve round-trip, partial-unique enforcement. Integration — GraphQL create→probe→
delete; deletion blocked while a lease is active. Reuse the `local` provider for no-network tests.

### PLAN 2 — Environment lease lifecycle + reuse/retain (features 2, 13, 18, 24-reuse) — **L**

Turns the ephemeral `runTaskInSandbox` into a leased, reusable, recoverable run.

**Prisma** (`environment.prisma`):
```prisma
enum LeaseStatus  { active released expired failed retained pending_cleanup }
enum LeasePolicy  { ephemeral reuse_by_environment reuse_by_execution_workspace retain_on_failure }
enum CleanupStatus { pending success failed }

model EnvironmentLease {
  id                  String        @id @default(cuid())
  workspaceId         String
  environmentId       String
  environment         Environment   @relation(fields: [environmentId], references: [id], onDelete: Cascade)
  executionWorkspaceId String?
  taskId              String?       // our issue analogue
  runId               String?       // agent run id
  status              LeaseStatus   @default(active)
  leasePolicy         LeasePolicy   @default(ephemeral)
  provider            String?       // sandbox provider key
  providerLeaseId     String?       // e.g. e2b sandbox id, k8s pod name
  acquiredAt          DateTime      @default(now())
  lastUsedAt          DateTime      @default(now())
  expiresAt           DateTime?
  releasedAt          DateTime?
  failureReason       String?
  cleanupStatus       CleanupStatus?
  metadata            Json?
  @@index([workspaceId, environmentId, status])
  @@index([status, expiresAt])
}
```

**Server services** (`apps/web/src/server/services/environment-leases.ts` + upgrade `sandbox-run.ts`):
- `acquireLease({workspaceId, environmentId, policy, executionWorkspaceId?})` — for `reuse_*` policies,
  first look for a live reusable lease (port `findReusableSandboxProviderLeaseId`,
  `sandbox-provider-runtime.ts:283`) via a guarded `updateMany` (atomic claim, mirrors
  `claimCommandsForAgent`, `runner-commands.ts:209`); else `provider.provision` and insert a new lease.
- `releaseLease(id, status)` / `releaseLeasesForRun(runId)` — for `ephemeral`, `handle.destroy()` +
  mark `released`; for `reuse_*`, keep provider machine, mark `released` but retain `providerLeaseId`;
  for `retain_on_failure` on error, mark `retained` (don't destroy).
- `reapStaleLeases(now, graceMs)` — reaper cron: leases past `expiresAt` or whose run is terminal →
  destroy provider machine + mark `expired`/`pending_cleanup`→`success`. **Reuse the existing
  reap-stale-work cron** that already runs `reapStuckRunnerCommands` (`runner-commands.ts:170`).
- Requires `SandboxProvider` to gain **resume/destroy-by-id**: extend `sandbox/types.ts`
  (`provider.resume(providerLeaseId)` + `provider.destroyById(id)`) — implement for `local`
  (dir still exists) + `kubernetes` (pod by name); cloud providers throw "reuse unsupported" until wired.
- Rewrite `runTaskInSandbox` to: `acquireLease` → run in leased handle → `releaseLease(policy)`
  (replaces its always-destroy `finally`). Persist result on the lease `metadata` for recovery.

**GraphQL:** `environmentLeases(workspaceId, environmentId?)` query; `releaseLease`/`destroyLease`
admin mutations. Surface `providerLeaseId`, `status`, `lastUsedAt`.

**UI:** a "Leases" tab on the Environment detail page — live table (status pill, provider, age,
last-used, task/run link, manual **Release**/**Destroy**). Component `EnvironmentLeaseTable.tsx`.

**Security:** reuse only within the SAME `workspaceId` + environment (never cross-tenant machine reuse).
Reaper is idempotent and must not destroy a lease already re-claimed by a live run (compare-and-set on
`status`, port the finalization CAS discipline from `doc/execution-semantics.md:124-133`).

**Tests:** acquire→reuse hits the same `providerLeaseId`; ephemeral destroys; retain_on_failure keeps
the machine; reaper expires stale + skips live; concurrent acquire (two runs) yields exactly one new
lease (atomic-claim test). Local provider only — no cloud creds.

**Server services** (`apps/web/src/server/services/execution-workspaces.ts` +
`execution-workspace-policy.ts`):
- Port the **pure resolver** first (`execution-workspace-policy.ts:48-284`) — no DB — it's the
  highest-value, lowest-risk piece: `resolveEffectiveWorkspaceStrategyType`, `isUnrunnableWorktreeCombo`
  (worktree needs a project or a bound reusable workspace — the recent `git-worktree` heartbeat fix
  suggests this is load-bearing), `resolveExecutionWorkspaceEnvironmentId` (agent→instance→default
  precedence).
- `realizeExecutionWorkspace({strategy, projectWorkspace, lease})` — replaces the inline clone in
  `sandbox-run.ts:109`: `project_primary` (clone/pull into cwd), `git_worktree` (git worktree add off
  baseRef), `adapter_managed` (metadata-only), `cloud_sandbox` (clone inside the leased sandbox). Each

### PLAN 4 — Environment probe + execution policy / allowlist / low-trust containment (features 20, 34, 35, 36, 37) — **M**

Two security-critical pure guards + a probe. High value, low surface.

**Prisma:** none new for the guards (policy lives in workspace settings JSON). Optional: a
`WorkspaceExecutionPolicy` row `{ workspaceId @unique, executionMode: "any"|"kubernetes", enableIsolatedWorkspaces }`.

**Server services:**
- `execution-allowlist.ts` (port `execution-allowlist.ts:54-103` verbatim — it's already pure &
  DB-free): `evaluateExecutionAllowlist(policy, {driver, provider})`. Call it in `acquireLease`
  (Plan 2) and reject with a structured `execution_denied` error before provisioning.
- `low-trust-containment.ts` (port `low-trust-runtime-containment.ts:44-105`): `assertLowTrustWorkspaceIsolation`
  (requires `driver:"sandbox"` + isolated execution workspace) + `assertLowTrustRuntimeServicesAllowed`.
  Wire our trust/governance resolution (`governance.prisma`, `trust.ts`) into its `resolution` input —
  this is the one place the execution domain **consumes** (not rebuilds) the SDK/governance boundary.
- `probeEnvironment(environmentId)` — driver-specific: `local` → host info; `ssh` → `resolveHostSSHConfig`
  + a no-op remote command via existing `runCommandOnHost` (`runner-commands.ts:128`); `sandbox` →
  `provider.provision` a throwaway handle, run `echo ok`, destroy (reuse `isSandboxProviderConfigured`
  first to fail fast on missing creds). Returns `{ok, driver, summary, details}`.
- **Pre-dispatch config gate** (feature 37): before `runTaskInSandbox`/dispatch, collect required
  secret bindings from the agent's adapter `configSchema` + environment config secret-refs; if any are
  unresolved in the vault, return a `configuration_incomplete` result that moves the task to `blocked`
  with the named missing binding — do NOT provision (port `heartbeat.ts:393-397` semantics).

**GraphQL:** `probeEnvironment(id)` mutation (returns probe result); `workspaceExecutionPolicy` query +
`setWorkspaceExecutionMode` admin mutation.

**UI:** Environment card **Probe** button + result panel (component from Plan 1). A workspace
Settings → "Execution policy" toggle (`any` vs force-`kubernetes`, enable isolated workspaces).

**Security:** the whole point — `executionMode=kubernetes` forces untrusted tenants onto the k8s
sandbox and denies local/ssh/plugin; low-trust runs are refused unless sandboxed + isolated. Enforced at
`acquireLease` so no code path can bypass it. Admin-only policy mutation.

**Tests:** allowlist truth-table (port the existing `execution-allowlist.test.ts` cases), low-trust
assertions (denied driver/workspace/boundary), probe happy/fail per driver (local + local-sandbox),
pre-dispatch gate blocks on missing secret + surfaces the binding name.

### PLAN 6 — Execution-target transport resolution + run-log streaming + live status + in-sandbox bridge (features 19, 22, 23, 25, 41, 42) — **M**

Depth polish that makes the above production-grade.

- **Unified runtime driver interface** (feature 22/23): introduce `EnvironmentRuntimeDriver`
  (`acquire/release/realize/execute`) with `local` / `ssh` (wraps `runCommandOnHost`) / `sandbox`

- **Execution-target resolver** (feature 19): `resolveExecutionTarget(environment, adapter, lease)` →
  `{kind:"local"} | {kind:"remote", transport:"ssh"|"sandbox", remoteCwd, spec|providerKey}` — port
  `environment-execution-target.ts:13`. Drives which transport the adapter invocation uses.
- **Run-log streaming** (feature 19/41): stream sandbox stdout/stderr to the task timeline mid-run
  instead of batch-at-end. Add an `onLog` callback to `SandboxHandle.exec` and a `taskRunStatus`
  GraphQL subscription (or poll) backed by an in-memory `runRuntimeStatus` map (port

**Plugin driver RPC** (feature 25) is explicitly **deferred** — our `registerSandboxProvider` +
`loadOptionalModule` seam covers the near-term "add a provider" need without a plugin-worker process.

**Tests:** target resolution per driver×adapter; streaming callback ordering; redaction of secrets in
live status; bridge token scoping (run id enforced, host JWT never exposed).

## 3. Dependencies, ordering & sizing

```
Plan 1 (Environment model + CRUD) ── M ── keystone, no deps
   ├── Plan 2 (Leases + reuse/reap) ─────── L ── needs Env; extends sandbox-providers (resume/destroyById)
   │      └── Plan 5 (Custom images) ─────── L ── needs Env + Leases; extends providers (snapshot)
   ├── Plan 3 (Execution workspaces) ─────── L ── needs Env (env-id precedence); pure resolver first
   └── Plan 4 (Probe + policy/containment) ─ M ── needs Env; consumes governance/trust boundary
Plan 6 (transport/streaming/bridge) ─────── M ── polish; needs Plan 1–2, benefits from 3
```

**Recommended sequence & sizing:**

| Order | Plan | Size | Rationale |
|-------|------|------|-----------|
| 1 | **Plan 1 — Environment model + CRUD** | **M** | Keystone; unblocks everything. |
| 2 | **Plan 4 — Probe + execution policy/allowlist/low-trust** | **M** | Security-critical, mostly *pure* ports; cheap once Env exists; gates lease acquisition. |
| 3 | **Plan 3 (resolver slice) — workspace policy resolver** | **S** | Pure, DB-free, immediately useful (fixes worktree-without-project runnability); do before full WS. |
| 4 | **Plan 2 — Lease lifecycle + reuse/reap** | **L** | Biggest behavioral upgrade to `runTaskInSandbox`; needs provider resume/destroy. |
| 5 | **Plan 3 (rest) — ExecutionWorkspace + realization + ops log** | **L** | Real worktree/branch machinery. |
| 6 | **Plan 6 — transport resolution + streaming + bridge** | **M** | Production-grade run UX. |
| 7 | **Plan 5 — Custom-image capture + setup terminals** | **L** | Highest effort, most provider-specific; last. |

**Quick wins to land first (S):** the pure `execution-allowlist` + `low-trust-containment` ports
(feature 34/36) and the pure workspace-policy resolver (feature 31) — high safety/behavior value, no
schema, trivially unit-testable, and they harden the *existing* `runTaskInSandbox` immediately.

## 4. Boundary (🚫 — do NOT build)

- **Human auth / login / sessions**, **billing/plans**, **orgs**, **workspaces (tenant containers)**,
  **RBAC/roles/permissions** — all `@buildbase/sdk`-owned. Our execution code only *consumes*
  `workspaceId` scoping and the admin check; it must not introduce its own tenant/user/permission model.
- The **trust/governance** resolution that Plan 4's low-trust containment consumes already exists
  (`governance.prisma`, `agent-authz.prisma`, `trust.ts`) — wire into it, don't duplicate it.
- The **secrets vault** (`Secret`/`SecretVersion`/`SecretBinding`, `resolveWorkspaceSecret`) already
  exists — all environment config secrets and setup-connection details reuse it (BYO credentials,
  never operator-owned).
