## 0. Executive summary

Paperclip is a **self-hostable single-binary control plane**: one `paperclipai` CLI does interactive onboarding, diagnostics, config management, DB backup, server start, *and* a full REST client (companies/issues/agents/routines/secrets/etc.). It ships a formal **two-mode deployment model** (`local_trusted` vs `authenticated`, with `private`/`public` exposure and a separate `loopback|lan|tailnet|custom` bind model), a rich JSON config schema, first-class Docker/Compose/Podman-Quadlet/ECS packaging, an embedded Postgres so it runs with zero external deps, and enforced **low-trust containment presets** (`standard` / `low_trust_review`) plus an isolated untrusted-PR-review Docker workflow.

Our monorepo is architecturally different and much thinner on this domain:

- **Deployment**: we are a **Vercel-hosted SaaS** (`apps/web`) plus an optional **self-hosted Docker Compose** (`apps/web/self-hosted/`, `ghcr.io` image). We have **no deployment-mode concept** (no local_trusted/authenticated/exposure/bind model) — auth is always-on via buildbase. Env is a flat `zod` schema in `apps/web/src/server/env.ts`.
- **CLI**: `@agentcenter/runner` is a **narrow, stateless agent-runner daemon** (`login`/`start`/`run-once`/`run-task`/`adapters`) — its differentiator is NAT-safe outbound-only polling. It is **not** an operator/admin CLI: no onboard, doctor, configure, db-backup, no REST-client subcommands, no server-start.
- **Trust presets**: we have `packages/utils/src/trust.ts` (`evaluateTrust`, levels untrusted/low/standard/trusted, `lowTrustContainment`, `requireUntrustedPrReview`) — a **pure decision function** with a comparable model, but **no runtime sandbox/isolated-workspace enforcement, no fail-closed managed low-trust runs, and no untrusted-PR-review container**.

Biggest gaps (all owned by us, not buildbase): **self-host onboarding/doctor CLI**, **deployment-mode + bind model**, **structured config file**, **embedded-DB zero-dep story**, and **runtime low-trust containment + untrusted-review sandbox**.

## 8. Boundary notes (buildbase)

- **Human auth / first-admin / sign-up disabling** (§1.4–1.5, §4.6): buildbase owns human identity/billing/hosting-account. Paperclip's `local_trusted` (no-login) and `bootstrap-ceo` invite have **no clean analog** while buildbase is mandatory — a self-host "local_trusted" mode would mean *bypassing* buildbase human-auth, which is a product/boundary decision, not just eng.
- Everything in **§2 (operator CLI), §3 (trust presets/containment), §4 (config file, storage, secrets, embedded DB), §5 (Docker/self-host packaging)** is squarely **ours** and portable without touching buildbase.
- Our **NAT-safe outbound-only runner** (`packages/runner/README.md`) is a genuine differentiator Paperclip's CLI model does not emphasize — worth preserving as the agent-execution path even as we add operator tooling.
