# Feature Priorities — what's required vs what's present

This is the prioritized catalog. Each significant feature has its own file in `features/`
(`P{n}-<slug>.mdx`) with: what it is, **verified** monorepo status (file evidence), gaps, and what's
required. This index is the map.

## Does the system work today? — YES (standalone)

The platform **boots and runs the full agent loop without any pending item.** Verified end-to-end:
an agent authenticates + fetches work (`/api/agents/me/context`), receives a task
(live-gateway **or** `/api/tasks/checkout`), executes (`sandbox-run.ts` → `local` provider or a
connected runner), submits deliverables (`/api/tasks/[id]/deliverables`), and a human reviews
(`reviewTaskByHuman` / approvals / `/review`). Startup has **no hard dependency** on plugin-runtime,
tools, or MCP. The one external requirement to run an agent *for real* is a credential — a
sandbox-provider key **or** a connected runner via the live gateway (both code paths are built).

## Priority definitions

- **P0 — Foundational.** The platform cannot function without it. → **all Present.**
- **P1 — Production-critical.** Needed to run agents in production (execution, secrets, cost control,
  recovery, memory, governance). Mostly Present; live execution gated on a real provider key.
- **P2 — High-value depth, buildable now.** Real capability/UX with existing backends. Present/partial.
- **P3 — Deferred / optional.** Infra-gated runtime (plugin worker, tools, MCP, workspace realization),
  buildbase-owned, or polish (dark mode). Missing/partial **by design**.

Gate legend: `buildable-now` · `needs-provider-key` (real sandbox/LLM key) · `needs-cloud-key`
(AWS/GCP/Vault) · `infra-gated` (cron/long-lived server/worker) · `buildbase-owned`.
