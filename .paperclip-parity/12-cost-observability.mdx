# Cost / Usage / Telemetry / Observability — Parity Gap Analysis

## Boundary (memory: buildbase-boundary)

buildbase owns **human billing/payments and plan entitlements** only. **Usage/cost
_attribution_ for agents is ours.** Both codebases respect this: Paperclip's
`cost_events` + `finance_events` and the monorepo's `CostEvent` + `LedgerEvent` are
workspace/company-scoped agent-cost ledgers, never human card billing. The monorepo
is explicit about the split — Epic #4 (`finance.prisma`, agent LLM/run cost + budgets)
vs Epic #16 (`ledger.prisma`, human business P&L), never conflated.

## Executive summary

The monorepo is **already at strong parity** on the core cost/budget spine. It has an
immutable `CostEvent` ledger with the same attribution dimensions
(agent/task/project/issue/biller/model/provider/tokens/cents), budget policies with
soft-warn + hard-stop + auto-pause + approval-gated resume, running quota windows,
a unified `costBreakdown` group-by query, cost trend, finance summary, per-agent window
spend, live incident subscriptions, and shipped dashboards (`/finance`, `/ledger`,
`/observability`, `/monitors`, `/analytics`). The monorepo even **exceeds** Paperclip
with on-demand `Monitor` thresholds and a first-class human P&L ledger.

The **real gaps** are the "second half" of Paperclip's cost/observability story:

1. **Non-inference finance ledger** (`finance_events`) — platform fees, credit
   purchases/refunds/expiry, BYOK fees, gateway overhead, training/storage charges,
   manual adjustments, debit/credit, estimated flag, external invoice id. **❌ absent.**
2. **Provider quota-windows polling** — live rate-limit / credit windows pulled from
   provider APIs via adapters (`getQuotaWindows`). **❌ absent.**
3. **First-party telemetry pipeline** — schema-led event contract, proposal workflow,
   PII/redaction boundary, retention classes. **❌ absent** (only in-memory notification
   counters).
4. **OpenTelemetry tracing** (opt-in, traces-only). **❌ absent.**
5. **Structured-logging depth** — pino + secret redaction + HTTP log policy + per-run
   log store (S3, sha256, offset reads). **🟡 home-grown JSON console logger only.**
6. **Smaller deltas** — recursive issue-tree cost+runtime rollup, project-scope budgets,
   richer `billingType` enum with split API/subscription reporting, `unpriced` cost state.

## Gap implementation plans

### GAP 1 — Non-inference finance ledger (`FinanceEvent`)  — size **M**
Mirrors Paperclip `finance_events.ts` + `finance.ts`. Distinct from `LedgerEvent` (human P&L)
and `CostEvent` (inference). Captures account-level provider money: credit purchases/refunds,
platform/BYOK fees, gateway overhead, training/storage, manual adjustments.

- **prisma** (`finance.prisma`): `model FinanceEvent { id, workspaceId, agentId?, taskId?,
  projectId?, issueId?, costEventId?, billingCode?, description?, eventKind (enum), direction
  (debit|credit, default debit), biller, provider?, model?, pricingTier?, region?, quantity?,
  unit (enum), amountCents Int, currency @default("USD"), estimated Boolean @default(false),
  externalInvoiceId?, metadataJson Json?, occurredAt, createdAt }`. Enums `FinanceEventKind`
  (14 kinds — copy from `constants.ts:745`), `FinanceDirection`, `FinanceUnit`. Indexes on
  `(workspaceId, occurredAt)`, `(workspaceId, biller, occurredAt)`, `(workspaceId, eventKind,
  occurredAt)`, `(workspaceId, direction, occurredAt)`, `costEventId`.
- **server**: `services/finance-events.ts` → `recordFinanceEvent` (validate FK-belongs-to-
  workspace, no re-derivation), `summary` (debit/credit/net/estimated/count), `byBiller`,
  `byKind`. Reuse Prisma `aggregate`/`groupBy`.
- **API**: GraphQL `financeEventSummary`, `financeByBiller`, `financeByKind`, `financeEvents`
  queries + `ingestFinanceEvent` mutation (admin/board role). Optional REST
  `POST /api/finance-events` mirroring cost-events route with a `FINANCE_REPORT` capability.
- **UI**: new tab on `/finance` page ("Financial") — summary tiles (debit/credit/net/estimated),
  by-biller card, by-kind card, recent finance-event timeline. Reuse existing Card/Badge.
- **security**: workspace-scoped everywhere; write gated to admin (buildbase role), never agent
  API key (these are human-entered account charges). Integer cents only. FK-belongs-to-workspace
  checks like `finance.ts assertBelongsToCompany`.
- **tests**: ingest validation, debit/credit netting, estimated split, workspace isolation,
  cost-event linkage.

### GAP 2 — Provider quota-windows polling  — size **M**
Mirrors `quota-windows.ts` + `types/quota.ts`.

- **types** (`@agentcenter/utils` or shared): `QuotaWindow { label, usedPercent, resetsAt,
  valueLabel, detail }`, `ProviderQuotaResult { provider, source?, ok, errorFamily?, error?,
  windows[] }`.
- **server**: `services/provider-quota.ts` → `fetchAllQuotaWindows(workspaceId)` fans out over
  registered adapters that implement an optional `getQuotaWindows()`, `Promise.allSettled` +
  per-provider ~20s timeout, failures returned as `{ ok:false }` rather than throwing. Add the
  optional hook to the adapter interface.
- **API**: GraphQL `providerQuotaWindows` query (admin-gated), short cache (reuse
  `server/cache.ts`) since provider APIs are rate-limited.
- **UI**: `ProviderQuotaCard` on `/finance` or `/observability` — per-provider windows with
  used% bars + reset countdown + credit remaining.
- **security**: validate workspace resolves; requires provider credentials — board/admin only;
  never expose raw credentials, only derived windows.
- **tests**: adapter fan-out, one-provider-timeout-doesn't-block-others, error shaping.
- Flag: `provider_quota` (default off until an adapter implements the hook).

### GAP 3 — First-party telemetry pipeline  — size **L**
Mirrors `packages/shared/src/telemetry/*` + `TELEMETRY_WORKFLOW.md` + `retention.ts`.

- **package** `packages/telemetry`: `generated/telemetry.ts` (event-name union
  `EventName`, `EventDimensionsMap`, `SCHEMA_VERSION`, `makeEvent`/`makeBatch`), `client.ts`
  (queue + flush + **swallow unregistered names**), `events.ts` (typed emit helpers),
  `retention.ts` (`RETENTION_DAYS` classes + `EVENT_RETENTION_CLASS`), `README.md` (PII/secret
  emission boundary; primitives-only dimension values).
- **proposal workflow**: `scripts/extract-proposed-events.mjs` scanning `@ts-expect-error --
  proposed-telemetry(<issue>): <rationale>` markers; a doc `docs/TELEMETRY_WORKFLOW.md`.
- **server sink**: `services/telemetry-sink.ts` receiving batches; canonicalization at the
  receiving layer (not emitters); persistence to a `telemetry_events` table or external
  sink; retention pruning job keyed by class window.
- **UI**: none required initially (data-infra concern); optionally surface event volume on
  `/observability`.
- **security**: hard boundary — no PII/secrets/prompts/model-output/private-paths in dimensions;
  primitives only (`string|number|boolean`); reuse existing redaction; drop `null`/objects.
- **tests**: unregistered-name swallow, dimension primitive validation, retention-class mapping,
  extractor provenance (repo-relative paths only).
- Flag: `telemetry` (default off). **Scope note:** this is the biggest lift; land as its own epic.

### GAP 4 — OpenTelemetry opt-in tracing  — size **S–M**
Mirrors `doc/observability.md`.

- **bootstrap**: extend `apps/web/instrumentation.ts` `register()` — when
  `OTEL_EXPORTER_OTLP_ENDPOINT` is set, dynamically import `@opentelemetry/sdk-node` +
  `auto-instrumentations-node` (optional peer deps, not in default lockfile) and start the SDK;
  select exporter by `OTEL_EXPORTER_OTLP_PROTOCOL` (grpc default); disable chatty `fs`/`dns`/`net`
  instrumentations; **zero import / zero overhead when the env var is unset**; single warn on
  unknown protocol; single diagnostic if packages missing (server stays up).
- **docs**: `docs/observability.md` (protocol→exporter table, env setup, traces-only scope).
- **security**: no PII in span attributes; keep default sampling; endpoint from env only.
- **tests**: unit — resolver picks exporter by protocol; boot with endpoint unset imports nothing.

### GAP 5 — Structured-logging depth (pino + redaction + run-log store)  — size **M**
- **pino** (`S`): replace/wrap `server/logger.ts` with pino + pino-http; dual transport
  (pretty console + JSON file), level policy (silence health 200s, warn 4xx, error 5xx), redact
  `authorization`/secrets — mirror `middleware/logger.ts`, `redact-sensitive.ts`,
  `http-log-policy.ts`, `log-redaction.ts`. Wire `error-tracking.ts` to the same pino instance.
- **run-log store** (`M`): `services/run-log-store.ts` — `begin/append/finalize/read` per
  heartbeat run; local-file default, S3 provider (reuse existing storage), sha256, gzip,
  offset/range reads; retention job. Ties into the remote-exec robustness backlog (memory).
- **tests**: redaction never leaks secrets; range reads; finalize sha256; retention purge.

### GAP 6 — Smaller deltas  — size **S** (each)
- **A9/A12 issue-tree rollup**: add a `costByIssueTree(issueId, excludeRoot)` GraphQL query using
  a recursive descendant CTE over `Task/issue` parent links, summing `CostEvent` + distinct-run
  wall-clock runtime (join run/heartbeat durations). Port `costs.ts issueTreeSummary`.
- **A10 rolling window spend**: `costWindowSpend` query (5h/24h/7d per provider) — small
  group-by, add to `/finance`.
- **A14 billingType**: widen enum to Paperclip's 6 values; add split API-vs-subscription run
  counts + token sums to `costBreakdown`. Migration + report expression change.
- **B7/B8 budget scope+window**: add `project` to `BudgetScope`, `lifetime` to `BudgetWindow`;
  extend enforcement + upsert.
- **A13 unpriced state**: add `costStatus` (`reported`|`unpriced`) to `CostEvent` for
  provider-cost-pending events + a repricing path.

## Notes / cross-refs
- The monorepo trusts caller-reported `amountCents` (like Paperclip) — **neither** derives cost
  from a server-side model-price table; a `MODEL_PRICING` table is optional future depth, not a
  Paperclip parity gap.
- `/monitors` (on-demand thresholds) and the human `/ledger` P&L are monorepo features Paperclip
  lacks — no action needed; note them as differentiators.
- Prioritization (aligns with memory backlog): GAP 5-run-log + GAP 2-quota feed the remote-exec
  robustness story; GAP 1-finance and GAP 6 are quick attribution depth; GAP 3-telemetry and
  GAP 4-OTel are standalone observability epics.
