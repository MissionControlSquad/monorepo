# 08 — Work items (issues / tasks / comments / documents / artifacts / runs)

**Domain:** the full work lifecycle — create → assign → checkout/run → comment → produce artifact/deliverable → review → PR/merge.
**Status legend:** ✅ Present · 🟡 Partial · ❌ Missing · 🚫 buildbase-owned (skip)
**Sizes:** S ≈ ≤2d · M ≈ ~1wk · L ≈ multi-week.

> **Scope note.** The heartbeat *engine / scheduling / watchdog cron* lives in domain `09-heartbeat-scheduling.mdx`. This doc covers the **work-item-facing** slices of runs: the run record as a first-class execution history on a task, run→artifact linkage, run→comment, run logs, and run-gated review. Where they overlap it is flagged `→09`.

> **Stack reality.** Paperclip DB = **Drizzle/Postgres** (`packages/db/src/schema/*.ts`), no Prisma. Its work item is called an **issue** (`issues` table), not "task". Its "review.ts" / "task-checkout.ts" etc. do **not** exist under those names — functionality is mapped below. Our monorepo = Prisma (`packages/database/prisma/schema`), GraphQL Pothos, Next app router.

## 0. Executive summary

We have a **strong flat task core** (status/priority/assignees, checkout lease, tree-hold, watchdog, relations, templates, recurring, plan-decomposition, approvals, deliverables + annotations/votes, messages, mention-auto-assign). Paperclip's work-item domain is **deeper on the execution/output/trust axis**. The parity gaps cluster into six themes:

| # | Gap theme | Impact | Size |
|---|-----------|--------|------|
| G1 | **Work-product taxonomy + PR-from-run** — we have only `Deliverable{markdown,code,file,link}`; Paperclip has `issue_work_products` with 7 types (pull_request/branch/commit/preview_url/runtime_service/artifact/document), a `reviewState` gate, `isPrimary`, `healthStatus`, provider, and `createdByRunId`. | High | L |
| G2 | **Untrusted-input containment (`low_trust_review`) + source-trust quarantine** — our `requireUntrustedPrReview` is a **dead toggle** (never consumed). Paperclip has a full preset/boundary/quarantine/promotion model. | High | L |
| G3 | **Per-task execution run record (`heartbeat_runs`)** — we have no run entity on a task: no run history, logs, liveness, retry/continuation, run→comment, run→artifact. (`→09` for the cron side.) | High | L |
| G4 | **Artifact upload pipeline (attachment → asset → work-product)** + agent upload skill — we store bytes inline on `Deliverable.storageKey` (R2) but have no asset/attachment separation, no agent-facing upload helper, no video/binary artifact story. | Med | M |
| G5 | **Document depth: text-anchored annotations w/ cross-revision re-anchoring + cooperative locks + comment-stream mirroring** — our deliverable annotations are quote-based & don't re-anchor; docs have no annotations, no locks. | Med | M/L |
| G6 | **Blocker diagnostics + dependency-resolved wakeups + typed thread interactions + rich comment presentation + external-object PR sync** — a cluster of smaller lifecycle refinements. | Med | S–M each |

## 1. Paperclip work-item model & lifecycle (reference)

**Core table `issues`** — `paperclip: packages/db/src/schema/issues.ts:22-168`.
- Status (flat, 7): `backlog, todo, in_progress, in_review, done, blocked, cancelled` — `packages/shared/src/constants.ts:193`.
- Priority (4): `critical, high, medium, low` — `constants.ts:214`. WorkMode: `standard, ask, planning, skill_test` — `:216`.
- Single assignee: `assigneeAgentId` / `assigneeUserId` (mutually exclusive).
- **Checkout/lease/execution lock:** `checkoutRunId`, `executionRunId`, `executionAgentNameKey`, `executionLockedAt` (`issues.ts:39-42`) — leases point at a **run**.
- **Provenance/autonomy:** `originKind` (`manual, routine_execution, stale_active_run_evaluation, harness_liveness_escalation, issue_productivity_review, stranded_issue_recovery, task_watchdog, plugin:*` — `constants.ts:279`), `originId`, `originRunId`, `originFingerprint`, `requestDepth` (cap 1024). Partial-unique indexes enforce **idempotency per origin** (`issues.ts:110-159`).
- **Autonomy policy:** `executionPolicy` jsonb (`normal|auto`), `executionState`, monitor fields, `sourceTrust` jsonb.
- Lifecycle timestamps: `startedAt/completedAt/cancelledAt/hiddenAt`.

**Lifecycle (implemented):** create (`backlog`, auto→`todo` if assignee) → assign (`PATCH`) → `POST /checkout` leases to a run, sets `in_progress`+`startedAt`, **refuses if unresolved blockers or an active pause-hold** (`services/issues.ts:6640,6623`) → status flows `in_progress→in_review→done`, side-branches `blocked/cancelled` → blocker resolves → dependency-wakeup fires. Related tables: `issue_relations` (only `blocks`), `issue_tree_holds`(+members), `issue_watchdogs`, `issue_recovery_actions`, `issue_comments`, `issue_documents`, `issue_work_products`, `issue_attachments`, `issue_approvals`, `issue_thread_interactions`, `issue_plan_decompositions`, `issue_labels`, `issue_reference_mentions`.

## 3. Gap deep-dives + implementation plans

### G1 — Work-product taxonomy + PR/preview/branch output types + review-state gate — **L**

**Why:** Today an agent run's output is only a `Deliverable{markdown|code|file|link}`. Paperclip treats output as a governed `issue_work_product` with a type taxonomy (PR/branch/commit/preview_url/runtime_service/artifact/document), a review-state machine, a single canonical primary per type, health, provider, and a link back to the run that made it. This is the backbone for PR review, deploy previews, and trust promotion (G2).

**Prisma** (`packages/database/prisma/schema/deliverable.prisma` or new `work-product.prisma`):
- Extend `DeliverableKind` → add `pull_request, branch, commit, preview_url, runtime_service`. Or (cleaner) introduce `WorkProduct` model to avoid overloading Deliverable; keep `Deliverable` as the `artifact/document/markdown/code` subset and add `WorkProduct` for execution outputs. Recommend **extend Deliverable** (less churn) with new fields:
  - `provider String?` (`paperclip|github|vercel|s3|custom`), `externalId String?`, `url String?` (exist), `reviewState WorkProductReviewState @default(none)`, `outputStatus WorkProductStatus?`, `isPrimary Boolean @default(false)`, `healthStatus String @default("unknown")`, `createdByRunId String?` (→ G3 `TaskRun`), `sourceTrust Json?` (→ G2).
  - New enums `WorkProductReviewState {none, needs_review, approved, changes_requested}`, `WorkProductStatus {active, ready_for_review, approved, changes_requested, merged, closed, failed, archived, draft}`.
  - Index `@@index([taskId, kind])`, partial-unique for `isPrimary` per (taskId, kind) — enforce in service (Prisma lacks partial unique on boolean cleanly; do it transactionally like `work-products.ts:54`).
- Migration + backfill existing rows `reviewState=none, isPrimary=true` for the latest per task/kind.

**Server service** `apps/web/src/server/services/work-products.ts` (mirror pc `work-products.ts:34`): `listForTask`, `getById`, `createForTask` (demote prior primary of same kind in a txn), `update` (flip reviewState/status; guard transitions), `remove`, `setReviewState`. Enforce transition legality (draft→ready_for_review→approved/changes_requested→merged/closed).

**API/GraphQL** (`src/server/graphql/mutations|queries`): `createWorkProduct`, `updateWorkProduct`, `setWorkProductReviewState`, `promoteWorkProduct`; queries `workProductsByTask`, `workProduct`, `workspaceWorkProducts` (extend existing deliverable resolvers).

**UI** (`apps/web/src/views` + `components/task`): extend `TaskDeliverables`/`DeliverableCard` to render type chips (PR/preview/branch), a **review-state badge + approve/request-changes buttons** for board reviewers, `isPrimary` star, health dot for preview/service. New `WorkProductReviewPanel` in `TaskDetailModal`/`TaskFullPage`. Extend `ArtifactsPage` filters by type + reviewState.

**Security:** review-state mutations gated to board/reviewer role; agents may create outputs but not self-approve (mirror `assertDeliverableMutationAllowedByRunContext`); low-trust outputs land `needs_review` (G2).

**Tests:** primary-demotion txn, illegal transition rejection, agent-cannot-self-approve, list-by-type. Size **L** (schema + service + UI + review flow).

### G2 — `low_trust_review` preset + source-trust quarantine/promotion (make `requireUntrustedPrReview` real) — **L**

**Why:** Our `AgentTrustProfile.requireUntrustedPrReview` (`governance.prisma:78`) is referenced only in schema/`trust.ts`/the mutation arg — **no code consumes it**. Paperclip's `low_trust_review` is the in-product containment for hostile/prompt-injected input (untrusted PRs, external tickets, dependency diffs): raw output is **quarantined**, not auto-promoted into higher-trust context, and a PR output sits at `needs_board_review` until a board user promotes it.

**Prisma:**
- `AgentTrustProfile`: add `trustPreset String @default("standard")` (`standard|low_trust_review`), keep `requireUntrustedPrReview` but **wire it**. Add `SourceTrustMetadata`-shaped `sourceTrust Json?` columns to `Deliverable`/`WorkProduct` (G1), `Message`, `Document`, `DocumentRevision` (mirrors pc `sourceTrust` everywhere).
- New `LowTrustBoundary` model (optional, phase 2): scope = company/project/rootTask/task/agent/toolClass + `outputPromotionTarget`.

**Server** `apps/web/src/server/services/source-trust.ts` (port pc `source-trust.ts`): `buildLowTrustSourceTrust(runId, agentId)`, `buildPromotedSourceTrust(...)`, `isLowTrustQuarantined(row)`, `redactQuarantinedBodyForHigherTrust`, `sanitizeQuarantinedCommentForHigherTrust`, `resolveActorSourceTrustForTask`. `low-trust-runtime-containment.ts` for tool-class gating (`git.read|github.pr.read|tests.local`), **fail-closed, narrower-wins** boundary resolution (`LOW-TRUST-PRESETS.md:15-27`).

**Wire points:** when a run/agent flagged low-trust writes a comment/work-product/document → stamp `sourceTrust={preset, disposition:'quarantined', sourceRunId, sourceAgentId}`; on read into a higher-trust actor's context → redact body to placeholder. A `pull_request` work-product from a low-trust run auto-sets `reviewState=needs_review` (ties to G1). Add `POST /tasks/:id/low-trust/promotions` (pc `issues.ts:6434`) → board promotes, stamps `buildPromotedSourceTrust`.

**UI:** quarantine banner on low-trust comments/outputs; "Promote" button (board only); trust-preset selector on agent settings (extend `setAgentTrustProfile`).

**Security:** this **is** the security feature — promotion is the only path out of quarantine, board-gated, audited; redaction must be applied at every higher-trust read path (comment render, run context assembly, plan-review context).

**Tests:** red-team route tests (mirror pc `low-trust-red-team-routes.test.ts`): quarantined body never leaks to a higher-trust reader; promotion requires board; fail-closed on ambiguous boundary. Size **L**.

### G3 — Per-task execution run record (`TaskRun`) w/ logs, liveness, run→comment, run→artifact — **L** (coordinate w/ `→09`)

**Why:** We have no first-class run on a task. Checkout leases (G2.2) already conceptually point at "a run" but we have no row. Without it there's no run history, no durable logs, no run-scoped attribution on comments/artifacts (blocks G1 `createdByRunId`, G6.2), no liveness/continuation, no productivity review.

**Prisma** new `run.prisma`:
- `TaskRun`: `id, taskId, agentId, workspaceId?, invocationSource (on_demand|scheduled|wakeup|continuation), status (queued|scheduled_retry|running|succeeded|interrupted|failed|cancelled|timed_out), startedAt/finishedAt, exitCode?, errorCode?, usageJson?, resultJson?, retryOfRunId?, scheduledRetryAt?, livenessState?, livenessReason?, continuationAttempt, logStore?, logRef?, logBytes?, logSha256?, stdoutExcerpt?, stderrExcerpt?, createdAt/updatedAt`. Relations back to `Task`, `Agent`.
- `TaskRunEvent`: `runId, seq, eventType, stream, level, message, payload` (ordered log stream).
- Add `Task.checkoutRunId/executionRunId` FK → `TaskRun` (make the lease reference concrete).

**Server:** `services/task-runs.ts` — `createRun`, `setRunStatus(id,status,patch)` (publish live event, clear runtime status on terminal — pc `heartbeat.ts:7503`), `setRunStatusIfRunning` guarded transition, `appendEvent`. `run-log-store.ts` (port pc `run-log-store.ts:32`: `begin/append/finalize/read`, local file + optional S3 mirror). `run-liveness.ts` classify (`→09`). `buildRunTaskComment` (pc `heartbeat-run-summary.ts:96`) — post a formatted result comment (needs G6.2 presentation).

**API/GraphQL:** `runsByTask`, `run`, `runEvents` (paginated); live subscription `task.run.status/log`. Mutations mostly internal (created by execution engine, domain 09) — expose cancel/retry.

**UI:** run history panel in `TaskDetailModal` (status timeline, log viewer with excerpt→full, retry/continuation chain), run badge on `TaskCard`.

**Security:** run rows are agent-created via API-key context; only the leasing agent/run may append; board may cancel. Log read gated by task ACL + low-trust redaction (G2).

**Tests:** status transition guards, terminal clears runtime, log store round-trip + S3 mirror, run→comment attribution. Size **L**. Heavy overlap with domain 09 — build the **model + log store here**, the cron/heartbeat driver there.

### G4 — Artifact upload pipeline (asset ↔ attachment ↔ work-product) + agent upload skill + video/binary — **M**

**Why:** We store deliverable bytes inline (`Deliverable.storageKey` → R2). Paperclip separates **`assets`** (immutable byte record: objectKey/sha256/contentType/byteSize) → **`issue_attachments`** (asset bound to an issue, optionally to a comment) → **work-product** (the deliverable referencing the attachment). This enables reuse, comment-inline images, video/pdf artifacts, and an agent-facing upload helper that cloud reviewers can reach.

**Prisma:**
- New `Asset`: `id, workspaceId, provider, objectKey, contentType, byteSize, sha256, originalFilename, createdByAgentId?/createdByProfileId?`. Unique `(workspaceId, objectKey)`.
- New `TaskAttachment`: `taskId, assetId (unique), messageId? (bind to a comment), createdAt`.
- Point artifact-type `Deliverable`/`WorkProduct` metadata at `assetId` (canonicalized `{contentType, byteSize, contentPath, openPath, downloadPath, originalFilename}` — pc `AttachmentArtifactWorkProductMetadata work-product.ts:58`).
