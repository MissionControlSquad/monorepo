# Memory Parity

## TL;DR

Paperclip's memory story is **two things**:

1. A **fully-specified but not-yet-implemented control-plane memory service** (`doc/plans/2026-03-17-memory-service-surface-api.md`, backed by `doc/memory-landscape.md`). No server tables, adapters, or routes exist in Paperclip yet — it is a design + adapter contract + rollout plan. Evals (`evals/promptfoo/tests/phase5-memory-control-surfaces.yaml`) assert the *intended* agent behavior (binding resolution, provenance audit, cost attribution).
2. A **shipped, runner-side, agent-facing file memory skill** (`skills/para-memory-files/`) — the PARA knowledge graph + daily notes + tacit `MEMORY.md` + `qmd` semantic recall + memory decay. This is the concrete "markdown provider" today.

Our monorepo implements a **deliberately simplified two-layer subset**: `Agent.memoryProvider` enum (`none|markdown|db`), an `AgentMemory` table with `sourceTaskId` provenance, pre-run injection for the `db` provider, and an admin mutation to set the binding — all MEMORY-flag gated. We have the *skeleton* of Paperclip's Layer 1 (binding + provenance) and Layer 2 (provider), but almost none of the control-plane depth (operations audit, cost attribution, hooks, adapters, inspect UI, extraction jobs, search tools).

Because Paperclip's server side is itself unbuilt, **parity here means matching the design intent**, not a shipped implementation. The high-value, differentiated pieces to build are: the **operations audit log**, **hook wiring (esp. post-run auto-capture, currently dead code)**, **cost attribution**, and a **memory inspect UI**.

## Gap Implementation Plans

Ordered by value/effort. Each is additive behind `FLAG_KEYS.MEMORY`.

### GAP-A — Memory operations audit log (features 19, 20, 25 foundation) · **Size: M**

The single most load-bearing missing table; everything else (cost, inspect, hooks) hangs off it.

- **prisma** (`packages/database/prisma/schema/memory-operation.prisma`):
  ```prisma
  model MemoryOperation {
    id             String   @id @default(cuid())
    workspaceId    String
    agentId        String?
    provider       String   // resolved binding value/key
    opType         String   // capture|record_upsert|query|list|get|forget|correct
    // scope
    projectId      String?
    taskId         String?
    runId          String?
    subjectId      String?
    // provenance
    sourceKind     String?  // issue_comment|issue_document|issue|run|activity|manual_note|external_document
    sourceRefId    String?  // commentId/documentKey/taskId/activityId/externalRef
    // outcome + usage
    success        Boolean  @default(true)
    error          String?
    latencyMs      Int?
    inputTokens    Int?
    embeddingTokens Int?
    outputTokens   Int?
    costCents      Int?
    attributionMode String? // billed_directly|included_in_run|external_invoice|untracked
    costEventId    String?
    createdAt      DateTime @default(now())
    @@index([workspaceId, agentId, createdAt])
    @@index([workspaceId, opType, createdAt])
    @@map("memory_operations")
  }
  ```
- **server**: add `recordMemoryOperation(input)` in `services/agent-memory.ts`; call it from every memory code path (`assembleInjectedMemory` → `query`, `appendAgentMemory` → `capture`).
- **migration**: additive create-table (follow repo's migration-safety lint, per recent commit `22001bbd2`).
- **tests**: unit — op row written on inject + append; provenance & scope fields populated; failure path sets `success=false,error`.
- Extend `AgentMemory` with `sourceKind`/`sourceRefId` (currently only `sourceTaskId`) to satisfy feature 20 — small migration.

### GAP-B — Wire post-run auto-capture hook (features 21, 22) · **Size: S**

`appendAgentMemory` is already written and unused — just needs a trigger. This is the highest-ROI fix (turns `db` from write-only-by-hand into a working loop).

- **server**: at run completion (where `heartbeat`/`sandbox-run` finalizes a task; `sandbox-run.ts` already threads `memoryProvider`), if provider === `db`, call `appendAgentMemory({workspaceId, agentId, content: <run summary/residue>, sourceTaskId})` and `recordMemoryOperation({opType:"capture"})`.
- Add a tiny hook dispatcher `runMemoryHooks(kind, ctx)` so `pre_run_hydrate` (existing) and `post_run_capture` share one surface (extensible to comment/doc capture later).
- **tests**: run completion with `db` provider creates one memory row + one capture op; `none`/`markdown` create none.

### GAP-C — Company default + resolution (features 1, 3, 4) · **Size: M**

- **prisma**: `MemoryBinding { id, workspaceId, key, provider, configJson, enabled }` + optional `MemoryBindingTarget { targetType(company|agent), targetId, bindingId }`. Minimal path: add `Workspace.defaultMemoryProvider` (or a single company binding row) first, keep `Agent.memoryProvider` as override.
- **server**: `resolveMemoryProvider(agent)` = `agent.memoryProvider (if set) ?? companyDefault ?? "none"`; replace the direct read in `agent-context.ts:27`.
- **graphql**: `setCompanyMemoryProvider` mutation (admin, MEMORY-gated), mirror of `setAgentMemoryProvider`; write an activity/audit entry on change (feature 5 gap).
- **tests**: resolution precedence (agent > company > none) — mirrors phase5 eval L14-40.

### GAP-D — Memory inspect UI (feature 28) · **Size: L**

Depends on GAP-A. New view under `apps/web/src/views/**` (follow `design-guide` + `frontend-design` skills; run Lazyweb for the dashboard/table pattern before building).

- **graphql** read queries: `agentMemoryEntries(agentId, cursor)`, `memoryOperations(filter, cursor)` (cursor pagination per plan AWS-lesson L406-416).
- **pages/components**:
  - *Agent settings → Memory* panel: current binding + provider picker (wraps `setAgentMemoryProvider`), company default indicator.
  - *Memory Operations Explorer*: filterable table (agent/task/run/source kind/date), success/latency/cost columns, source backlinks to task/comment/doc.
  - *Record list + detail*: entries with `sourceTaskId` backlink, supersede action (feature 29 hook).
  - Usage/cost summary tiles (use `dataviz` skill for any charts).
- **gating**: whole surface behind `MEMORY` flag + role check.
- **tests**: RTL render of panel/table; query returns workspace-scoped rows only.

### GAP-E — Adapter interface + provider registry (features 8-11) · **Size: L**

Formalize the current `switch` into a `MemoryAdapter` interface (`services/memory/adapters/`), with `db` and `markdown` (runner-file/no-op) built-ins implementing it, and capability flags. Enables later plugin/hosted (mem0/supermemory) adapters. Do this only after A-D prove the shape; otherwise it is premature abstraction over 2 providers.

### GAP-F — Agent memory tools + search (features 18, 27) · **Size: M**

Expose `memory.search`/`memory.note`/`memory.forget` to agents (tool-calls that hit `query`/`upsert`/`forget` + log ops). `db` provider search can start with Postgres `ILIKE`/`pg_trgm`; `markdown` maps to the runner `qmd` analog. Replaces the crude newest-20 bulk inject with real recall (feature 17/18 gap).

### GAP-G — Cost attribution + finance linkage (features 25, 26) · **Size: M**

Populate `MemoryOperation` usage fields from provider responses; when a memory op makes a *direct metered* model/embedding call, create a linked `cost_event`; subscription costs → `finance_events`; dedupe when `attributionMode = included_in_run`. Depends on our having a `cost_events`/`finance_events` ledger (verify separately). Add eval-metric counters (recall hit rate, extraction failures).

### GAP-H — Behavior eval suite (feature 30) · **Size: S**

Port `phase5-memory-control-surfaces.yaml` intent into our eval harness: binding-resolution precedence, provenance-audit field presence, no cross-company/global-default leakage.

## Notes / Caveats

- **Paperclip has no shipped server memory service** — its Layer-1 is design-only. Our `db` provider is actually *ahead* of Paperclip on control-plane *storage* (they store residue in the provider, not Postgres), but *behind* on operations audit, hooks, cost, and inspect.
- **Deferred async extraction, provider-native browse/graph, multimodal, cross-company sharing** (plan §"Not automatic" L520-527, Phase 5 L690-695) are explicitly out of scope even for Paperclip V1 — do not build.
- **BOUNDARY**: none of this touches human auth (buildbase-owned). Binding auth reuses existing `requireRole`/tenancy.
