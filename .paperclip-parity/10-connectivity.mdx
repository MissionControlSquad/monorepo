## 0. The load-bearing architectural difference (read first)

Paperclip and our monorepo both connect an **OpenClaw runtime** to a control plane, but the
**connection direction is opposite**, and that shapes everything else:

| | Paperclip `openclaw_gateway` | Our Live Gateway |
|---|---|---|
| Who dials whom | **Control plane → runtime** (Paperclip opens an outbound WS *to* the OpenClaw gateway server) | **Runtime → control plane** (the OpenClaw plugin dials *out* to our cloud WS) |
| NAT posture | Runtime must be reachable (LAN/tailnet/reverse-proxy/HTTPS) | **NAT-safe** — runtime needs only outbound egress |
| Device auth | Ed25519 signed challenge-response + auto device-pairing | Install-token → per-machine permanent token + nonce anti-replay |
| Reach model | Paperclip is a WS *client*; also HTTP/SSE (hermes) and cloud SDK (cursor) | We are the WS *server* (fan-in); plus outbound HTTP-poll runner |

Net: **our NAT-pull bridge is a real differentiator** (documented in memory), but Paperclip covers
a *much wider matrix of ways to reach a runtime*: outbound WS w/ crypto device pairing (openclaw),
outbound HTTP+SSE (hermes), and cloud-SDK background agents (cursor). We implement exactly one
transport shape (WS fan-in) plus an outbound HTTP-poll runner and a browser SSH-PTY relay. We have
**no hermes, no cursor_cloud, no inbound MCP tool-gateway, no cryptographic device pairing.**

Everything is flag-gated in our repo (`packages/utils/src/feature-flag-keys.ts`): `LIVE_GATEWAY`
(`live_gateway`, default false, L10/L51), `RUNNERS` (`runners`, L36/L79), `TERMINALS`
(`terminals`, L26/L68), `MULTI_PROVIDER_ADAPTERS` (`multi_provider_adapters`, L14/L56).

## 2. Gap deep-dives + implementation plans

### GAP-1 — Cryptographic device pairing for the Live Gateway (A5/A6/A13) · **size M**

**Why:** our install-token→permanent-token model authenticates the *machine token* but not a
*device keypair*; a leaked install token lets any host register. Paperclip signs an Ed25519 device
payload against a server nonce and supports operator-approved pairing. Closing this raises trust to
Paperclip's bar without changing our NAT-pull direction.

- **Prisma** (`packages/database/prisma/schema/live-gateway.prisma`): add `LiveGatewayDevice`
  { `id`, `machineFingerprint @unique`, `publicKeyRaw` (base64url Ed25519), `deviceId`
  (sha256(pubkey)), `status` pending|approved|revoked, `approvedByUserId?`, `approvedAt?`,
  `lastNonce?`, timestamps }. Keep `LiveGatewayConnection` for session/token; reference device.
- **Protocol** (`packages/types/src/live-gateway-protocol.ts`): add `mc.challenge` (server→plugin
  nonce, sent before accepting hello) and extend `MsgHello` with
  `device:{ id, publicKey, signature, signedAt, nonce }`. Bump a `protocolVersion` field.
- **Server** (`live-gateway-handler.ts:handleHello`): after nonce check, `crypto.verify(null,
  payloadBytes, publicKey, sigBytes)`; on unknown fingerprint create device `status=pending` and
  reject with a new `VMErrorCode` `device_pending`; expose an approve endpoint
  (`POST /api/live-gateway/devices/:id/approve`, board-only) mirroring Paperclip
  `device.pair.approve`. Reuse `consumeNonce`.
- **Plugin** (`packages/mc-bridge-plugin/src/ws-client.ts`): generate+persist an Ed25519 keypair
  (`~/.agentcenter/device-key.pem`), sign `v1|deviceId|fingerprint|signedAt|nonce`, retry once on
  `device_pending` after operator approval (mirror `autoPairOnFirstConnect`).
- **UI:** device list + approve in the Live Gateway settings wizard (pending badge).
- **Security/tests:** unit — bad signature, replayed nonce, fingerprint/pubkey mismatch, revoked
  device fail-closed; e2e — pair→approve→reconnect. Model on Paperclip
  `execute.ts:553-588,815-902`.

### GAP-2 — Hermes gateway adapter (HTTP + SSE) (Section B) · **size M**

**Why:** lets any Hermes API server (`hermes gateway run`) be reached as an agent runtime without a
persistent socket or our plugin — a second, simpler reach path. Pure outbound HTTP(S)+SSE.

- **Adapter registry:** seed an `AgentAdapter` row `type="hermes-gateway"`,
  `transport=gateway`, `authKind=apiKey`, `configSchema` = { `apiBaseUrl` (req), `apiKey`
  (req, secret), `sessionKeyStrategy`, `timeoutSec`, `eventReconnectMs`,
  `dangerouslyAllowInsecureRemoteHttp` }. Gate behind `MULTI_PROVIDER_ADAPTERS`.
- **Service module** (`packages/utils` adapter invocation, or a new `apps/web` service):
  `POST {apiBaseUrl}/v1/runs` → read `run_id`; open `GET /v1/runs/:id/events`
  (`Accept: text/event-stream`), parse `message.delta` + `run.<status>` (port
  `execute.ts:380-488`); poll `GET /v1/runs/:id` as fallback; `POST /v1/runs/:id/stop` on timeout
  with 10s grace. Bearer `apiKey`; lock critical headers; **hard-deny non-loopback `http://`**
  unless escape flag (port `transport-security.ts:12-29`).
- **Session resume:** persist `{ hermesSessionId, sessionKey }`; send `X-Hermes-Session-Key` +
  body `session_id`.
- **Secrets:** `apiKey` in the secret vault (domain 07), never in logs — reuse redactor pattern.
- **Tests:** SSE frame parse, terminal-status mapping, plain-HTTP guard, reconnect, stop-grace,
  auth-fail (401/403) classification. Mirror `hermes-gateway-e2e.sh`.

### GAP-3 — Cursor Cloud adapter (Section C) · **size M**

**Why:** offloads execution to Cursor's hosted background agents (no runtime to host at all) with
durable cross-heartbeat sessions and native PR flows.

- **Dependency:** add `@cursor/sdk`. **Adapter:** `type="cursor_cloud"`, `transport=cloud`,
  `authKind=apiKey` (`CURSOR_API_KEY`). Config: `repoUrl`(req), `repoStartingRef`,
  `repoPullRequestUrl`, `runtimeEnvType` (cloud|pool|machine), `autoCreatePR`, `model`,
  `instructionsFilePath`, `promptTemplate`.
- **Server:** create a durable Cursor agent, persist `{ cursorAgentId, latestRunId, runtime,
  repos }` (port `session.ts:31-61`); reuse agent across heartbeats when repo/runtime identity
  matches; each beat = one Cursor run; inject `PAPERCLIP_*`/`AGENTCENTER_*` env into cloud shell;
  stream `cursor_cloud.*` events into the task timeline.
- **Tests:** session-codec normalize/reuse, run mapping, env injection, PR-URL binding. Mirror
  `cursor-cloud/src/server/session.test.ts`, `execute.test.ts`.

### GAP-4 — Inbound MCP tool-gateway + run-scoped tokening + rate limits (Section D) · **size L**

**Why:** today agents that need governed tool access have no brokered inbound endpoint; Paperclip
exposes a named MCP endpoint bound to a profile with run-scoped, expiring tokens, per-company rate
limits, action-request approvals, and full audit. This is the biggest single gap and the security
spine for agent tool use.

- **Prisma (gateway-owned):** port `mcp_gateways`(+profile FK, `gateway_public_id`, `auth_config`,
  `header_policy`, `metadata_policy`), `mcp_gateway_tokens` (`token_prefix`, `subject_type`,
  `allowed_actions`), `tool_gateway_sessions` (`token_hash`,`expires_at`,`run_id`/`issue_id`/
  `project_id`), and `tool_gateway_rate_limit_counters` (`counter_key`,`window_ms`,`limit`,
  `reset_at`). Source SQL: `0159`+`0160`,`0151`,`0169` under
  `paperclip/packages/db/src/migrations/`. (The credential-vault tables —
  `connection_token_issuances` `0165` ttl≤900s, `tool_connection_installs` `0168`, `tool_*` catalog
  `0148` — are written by `server/src/services/tool-access.ts`, i.e. **domains 06/07**; coordinate,
  don't duplicate.)
- **API/WS:** MCP protocol handler `GET/POST /api/mcp/gateways/:publicId` (auth via
  `x-paperclip-tool-gateway-token`-equivalent or Bearer, port `tool-gateway.ts:39-70`); session
  create/revoke; tools discovery + call; action-request approve/decline; runtime-slot stop/restart;
  audit read. Enforce complete-mediation checks at call time
  (`doc/connections/SECURITY-THREAT-MODEL.md:142-157`).
- **Governance:** depends on the profiles/policies/catalog model (**coordinate with domains 06/07**
  — do not fork a parallel connection framework; see `doc/connections/README.md` D1).
- **Security/tests:** cross-company isolation, deny-by-default, revocation fail-closed, rate-limit
  window enforcement, redaction — port the negative-test matrix
  (`SECURITY-THREAT-MODEL.md:207-257`).
- **Sequencing:** land the token/session/rate-limit substrate first (M), then the MCP protocol
  surface (M) once 06/07 governance exists.

### GAP-5 — One-time agent-key claim ceremony for gateway onboarding (A13) · **size S**

**Why:** Paperclip separates the *gateway auth key* (control-plane→runtime) from a *claimed
one-time Paperclip agent key* (runtime→control-plane), so the runtime never holds a durable
board-scoped credential (`HERMES_GATEWAY_ONBOARDING.md:24-38,114-134`). Our install token doubles
as both, which is weaker.

- **Server:** on Live-Gateway/runner approval, mint a one-time `claimSecret`; add
  `POST /api/join/:requestId/claim-key` that returns a scoped agent key once, then burns the
  secret. Store only a hash.
- **Plugin/runner:** claim on first connect, persist the agent key separately from the install
  token; use it as the `Authorization: Bearer` for callbacks.
- **Tests:** double-claim rejected, claimed key is agent-scoped (not board), install token cannot
  call agent APIs.

## 3. What we lack, at a glance

- **Gateways/protocols absent:** `hermes_gateway` (HTTP+SSE), `hermes_local`, `cursor_cloud`
  (`@cursor/sdk`), and the **inbound MCP tool-gateway** — only enum slots reserved in
  `adapter.prisma:13-17`.
- **Auth depth absent:** Ed25519 device signing + operator device-pairing; run-scoped/short-TTL
  brokered token issuance; per-company protocol rate-limit counters; one-time agent-key claim.
- **Direction/reach absent:** we cannot *dial out to* a runtime (WS or HTTP) — we only accept
  fan-in or poll. No control-plane-initiated reach to a listening runtime.
- **What we already match or beat:** WS real-time OpenClaw reach (inverse, NAT-safe ✅), ping/pong +
  eviction heartbeat (beats Paperclip's timeout-only openclaw path ✅), durable at-least-once task
  delivery with acks + dead-letter ✅, nonce anti-replay ✅, an outbound HTTP-poll runner ✅, and a
  browser SSH-PTY relay ✅.

**Priority:** GAP-1 (M, hardens the one thing we ship) → GAP-4 substrate (L, security spine, gated
on 06/07) → GAP-2 (M) → GAP-3 (M) → GAP-5 (S).
