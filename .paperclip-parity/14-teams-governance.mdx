# Teams / Org-Chart / Boardroom / Governance / Agent-Companies

Boundary: **buildbase owns HUMAN orgs / workspaces / RBAC.** Everything below is about how
**AGENTS** are organized into companies/teams, their hierarchy, delegation, and the governance
that gates their work. In the monorepo every agent-domain model is `workspaceId`-scoped with **no FK**
to buildbase (design note "D5") — humans (`Profile`) only appear as approval *deciders*, never as org nodes.

Paperclip framing (`doc/PRODUCT.md`, `doc/GOAL.md`): Paperclip is the *control plane for autonomous AI
companies*. A **company** is the first-order object; every employee is an agent; the CEO is the root of an
org chart; all work traces up a goal hierarchy (**company → team → agent → task**); the human "board"
governs via approvals and budgets. The portable format is the markdown-first **Agent Companies Spec**
(`agentcompanies/v1`, `docs/companies/companies-spec.md`): `COMPANY.md` / `TEAM.md` / `AGENTS.md` /
`PROJECT.md` / `TASK.md` / `SKILL.md` packages, importable/exportable as git-native folders.

## Executive summary

The monorepo has ported the **runtime spine** of this domain well: agent org-chart with `reportsTo`
(Epic #19), an installable **Team catalog** (Epic #10), agent-domain **Approvals** (Epic #3), **agent-authz**
capability grants (#21, = Paperclip `principal_permission_grants`), **agent governance** provisioning knob
(A.4), per-agent **trust profiles**, workspace-scoped **budgets** with auto-pause (#4), **deliverable voting**,
and a **Boardroom** concierge chat (#15). Flags exist for each (`org_chart`, `skills_teams`, `governance`,
`agent_authz`, `budgets`, `voting`, `board_chat`).

The **biggest structural gap is the Agent-Companies package model** — Paperclip's entire portability story
is markdown `COMPANY.md`/`TEAM.md`/`AGENTS.md` packages (`agentcompanies/v1`) with a shipped **teams-catalog
package**, git/GitHub-native import graph, `.paperclip.yaml` vendor sidecar, collision handling, and a
README + Mermaid org-chart generator. The monorepo has **no `Company`/`AgentCompany` entity at all** (only
a goal-tree *level* named "company"), and its portability is a **credential-free JSON bundle**, not markdown
packages. Secondary gaps: **delegation is only convention** (no policy engine either side, but Paperclip
ships a rich CEO-delegation persona + hire-hook + goal-alignment; monorepo has neither), the **`hire_agent`
approval subject type is defined but unwired**, there is **no board-quorum/multi-approver** governance,
and no per-agent configurable approval-policy engine.
