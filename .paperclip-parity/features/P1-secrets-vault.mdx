# Secrets vault · P1 · 🟡 Local envelope complete; aws/vault stubs

**What it is:** encrypted secret storage with versioning/rotation, agent/adapter bindings, injection
into runs, audit-on-resolve, bulk import, personal secrets, and pluggable providers.

**Present in our monorepo (verified):**
- Store + crypto: `secret.prisma`, `secrets.ts`, `secrets-crypto.ts` (AES-256-GCM envelope under `SECRET_ENCRYPTION_KEY`).
- Create/update/status/rotate/version: full; `SecretVersion` append+retire, keyId for key-rotation.
- Bind/unbind + resolve/inject: `bindSecret`/`unbindSecret`, `mergeEnvBindings` (agent>adapter), `resolveEnvForAgent` (BYO cloud keys into the sandbox).
- Providers: `SecretProviderKind{env,aws,vault}`; **env `implemented:true`; aws/vault `implemented:false` ("coming soon")** (`packages/utils/src/secret-providers.ts`). Health-check persists healthy/lastCheckedAt/lastError.
- Audit-on-resolve: `SecretAccessEvent` (consumerType/configPath/outcome/runId), `recordSecretAccess`, per-binding injected/missing events.
- Import + personal secrets: `importSecrets` (.env), `Secret.personal` + owner-only authz.
- UI: `secrets/page.tsx` (providers + health-check button + bulk import + personal toggle).

**Gaps / pending:**
- **AWS/GCP/Vault providers are enum + config-validating stubs only** — no cloud SDK/HTTP client anywhere. Everything downstream works only for the local envelope. → **needs-cloud-key**.
- **AWS discovery** (import from Secrets Manager/SSM) missing (needs the aws resolver first).
- **References/usage drill-down** partial — bindings + access-events give indirect "what uses this"; no dedicated `secretReferences` query (buildable-now if wanted, but partly duplicates bindings).

**What's required:** real AWS/GCP/Vault credential resolvers (needs-cloud-key); optional `secretReferences` aggregation (buildable-now).

**Priority rationale:** Agents need provider keys injected securely; production needs the vault. The local envelope is production-usable today; external providers are optional depth.

**Depends on:** real cloud credentials for aws/vault backends.
